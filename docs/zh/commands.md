# 命令

**中文** | [English](../en/commands.md)

本模组只有一套命令：`/cofdebug`，用来查看各条规则的实际状态 —— 例如"锅为什么不结冰""物品有没有被消耗"。是否可用与所需权限由 `cofDebugCommand` 规则控制（默认 `2`，即 OP 可用；设为 `false` 则命令完全关闭）。

---

## 结冰检查 (`/cofdebug tick`)

### 语法
- `/cofdebug tick <坐标>`
    - `<坐标>` 目标方块的坐标

### 效果
- 手动步进一次结冰检查，报告目标、累计与本次结果。
- **会改动世界**：可能真的结冰并产出产物。
- 总开关（`waterCauldronFreezing`）关闭时拒绝执行。

## 数据查看 (`/cofdebug data`)

### 语法
- `/cofdebug data <坐标>`
    - `<坐标>` 目标方块的坐标

### 效果
- **只读**复述该坐标的完整条件与进度，不会创建任何数据文件。
- 报告项包括：规则当前值、实际被报告的位置、维度、方块、水位、水位条件、群系、降水、露天、方块光、累计进度、产物、下次结冰是否产出。
- **实际报告的位置可以不等于你输入的坐标**：优先用"结冰逻辑实际会处理的那口锅"（该列地表 / 地表下一格），找不到才沿地表往下探 4 格。

## 数据改写 (`/cofdebug data` 写)

### 语法
- `/cofdebug data <坐标> <值>`
    - `<坐标>` 目标方块的坐标
    - `<值>` 要写入的累计次数，`0` 表示清除记录

### 效果
- 改写该处的累计次数，写在与结冰逻辑相同的那口锅上。
- 输入坐标对不上时退回字面坐标，并在输出里点明，避免"写入成功却读不到"。
- **会改动数据**（不会结冰）。

## 物品交互 (`/cofdebug use`)

### 语法
- `/cofdebug use <坐标> [玩家]`
    - `<坐标>` 目标方块的坐标
    - `[玩家]` 动手的玩家，省略时取第一个在线玩家

### 效果
- 让该玩家用手上物品对该方块**真右键一次**，播报交互前后的变化。
- 报告项：执行者、手持物品（交互前）、交互后手上的物品、水瓶是否被消耗（仅手持水瓶时）、方块变化。
- **会改动世界**（等同于玩家自己操作）。

## 水桶校验 (`/cofdebug bucketcheck`)

### 语法
- `/cofdebug bucketcheck [玩家]`
    - `[玩家]` 用于模拟的玩家，省略时取第一个在线玩家

### 效果
- 调用原版"手上最终剩下什么"的判定，验证 `waterBucketNotConsumed` 规则。
- 报告项：期望值、放水与倒进锅两条路径的实际结果、两个对照（岩浆桶、空桶装水）。
- 用副本模拟，**实质只读**；创造模式下直接跳过。

## 声望查询 (`/cofdebug reputation`)

### 语法
- `/cofdebug reputation [玩家]`
    - `[玩家]` 要查询的玩家，省略时取执行命令的玩家

### 效果
- **只读**显示该玩家对"最近村民"（64 格内距离最近的一只）的声望。
- 报告项：村民（名称与坐标）、声望、是否达到铁傀儡防卫阈值（输出"是"或"否"，阈值为声望 ≤ -100）。
- 声望 = 账本条目数值 × 权重之和，权重为 `major_negative` -5、`minor_negative` -1、`minor_positive` +1、`major_positive` +5、`trading` +1；逐条明细见 `/data get entity <村民> Gossips`。
- 调试提示：世界里若残留多只村民，查询可能落在"另外一只"身上，测相关行为前建议先清场。
